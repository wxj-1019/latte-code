P0 优先事项：先做哪个？

两项都是核心缺失，但实施顺序影响后续开发效率

A

动态工作流引擎

JS 编排脚本 + 16并发代理池 + 检查点恢复

优势

  • 直接提升用户体验 — 大规模任务自动化
  • 与 Nudge Engine 形成闭环（学→自动执行）
  • 可复用现有 AgentTool 基础设施

挑战

  • 需要设计 JS 沙箱运行时
  • 代理池生命周期管理较复杂
  • WorkflowTool 目前是空存根

涉及改动：src/tools/WorkflowTool/、src/services/workflow/（新建）

B

内核级沙箱增强

bubblewrap(Linux) + Seatbelt(macOS) 四层隔离

优势

  • 安全基准对齐 Codex CLI 行业标准
  • 企业级用户核心诉求
  • Bun 运行时天然有利于沙箱集成

挑战

  • 深度系统级集成，平台差异大
  • Windows 沙箱方案不成熟
  • 测试困难（需要不同 OS 环境）

涉及改动：src/utils/sandbox/（扩展）、vendor/ 二进制依赖

推荐先做动态工作流

理由：它与 Nudge Engine 形成自动学习→自动执行闭环，这是 latte-code 区别于所有竞品的独特能力。沙箱增强偏基础设施，可以并行推进但不应该阻塞核心功能。
