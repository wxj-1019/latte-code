动态工作流引擎 — 完整设计

所有技术选择采用推荐方案，与现有架构深度融合

1. JS 沙箱：Bun vm 模块

零依赖，与 latte-code 同运行时，支持超时和内存限制。对比 Node.js worker_threads 或独立进程更轻量。

理由

  • Bun 原生，零额外依赖
  • 内置超时 + 内存上限
  • 项目已在多处使用 Bun 特性

限制

  • 不提供 OS 级别隔离
  • 脚本不能 import 外部模块（白名单机制）

2. 代理池：复用 spawnMultiAgent

Workflow Engine 调用已有的 spawnMultiAgent 管理子代理，与 AgentTool 共享同一套生命周期。

并发 16 上限、代理间通信、权限继承、worktree 隔离 — 全部复用。

3. 文件结构（新建 3 个模块）

路径职责
src/services/workflow/engine.ts脚本加载、沙箱执行、结果收集
src/services/workflow/pool.ts代理池管理（并发控制、生命周期）
src/services/workflow/nudgeIntegration.ts与 Nudge Engine 自动触发桥接
src/tools/WorkflowTool/WorkflowTool.ts从存根升级为完整 Tool 实现
src/commands/workflow//workflow 斜杠命令

4. 核心数据流

Nudge Engine 检测模式
│ → autoSkillify 生成 .claude/skills/_auto_xxx/SKILL.md
│
▼
Workflow Engine 收到触发（自动/关键词/手动）
│ → 加载 Skill → LLM 生成 JS 编排脚本
│ → Bun vm 沙箱执行脚本
│ ├─ script.spawn("agent-name", { task }) → pool.acquire()
│ ├─ agent 结果 → script 变量（不进 Claude 上下文）
│ └─ script.return(finalAnswer) → 回传 Claude
│
▼
结果反馈
│ → memdir 记录执行统计
│ → Nudge Engine 更新 Skill 置信度/使用频率
│ → 高频 Skill → 提升为永久 Skill
